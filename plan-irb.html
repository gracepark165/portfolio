IRB Helper

연구계획서를 입력하면 공용IRB 신청 서류 초안을 만드는 웹 서비스

1배경

임상연구 현장에서 IRB 신청과 보완 대응을 맡으며, 여러 문서에 흩어진 정보를 다시 찾아 정리하고 서식에 맞춰 옮기는 업무를 반복했습니다. 같은 연구 정보가 연구계획서·설명문·동의서에 각각 들어가다 보니, 한 곳을 고치면 다른 서류와 어긋나는 일이 생깁니다.

2문제 정의

대상공용IRB 신규 심의를 준비하는 연구자와 연구 실무자
상황같은 연구 정보를 여러 서류에 반복해서 옮겨 적는다
문제서류 간 정보 불일치(예: 계획서 60명, 동의서 50명)로 보완 요청이 생기고, 수정할 때마다 모든 서류를 다시 확인해야 한다
핵심 질문연구자가 한 번 확인한 사실을 여러 서류에 같은 기준으로 쓰게 하려면?

3목표와 설계 원칙

  • 반복 입력을 줄인다: 기존 계획서 초안을 올리면 질문 칸을 미리 채운다
  • 빈칸은 질문으로 바꾼다: 모르는 항목과 PI에게 물을 항목을 한곳에 모은다
  • 서류의 기준은 하나로: 같은 연구 정보를 모든 서류에 함께 반영한다

AI의 자유 작성이 아니라 “연구 사실 시트” 중심. 근거가 불확실한 내용은 임의로 채우지 않고 확인 항목으로 남긴다.

4사용자 흐름

연구 유형 선택→질문 답변 · 계획서 업로드→AI 정보 추출→연구 사실 시트 확인→HWPX 서류 생성→연구자 · PI 최종 검토

5AI와 사람의 역할

AI가 하는 일계획서에서 연구 정보 추출, 필드별 근거 정리, 서식별 초안 작성, 빈 항목을 질문으로 제시
사람이 하는 일연구 사실 시트의 값 확인, 불확실 항목 결정, PI 최종 확인과 제출

6핵심 기능

기능내용
유형 선택·질문 입력연구 유형에 맞는 질문만 보여 준다
초안 추출업로드한 계획서에서 필드별로 정보를 뽑는다
연구 사실 시트모든 서류가 참조하는 확인된 정보 한 장. 미확인 항목은 표시
PI 확인 목록연구책임자에게 물어야 할 항목을 모은다
HWPX 생성기관 공식 양식(한글 파일)으로 서류를 만든다

7시스템 구성

구성역할
웹 화면 (Vercel)유형 선택, 질문 입력, 사실 시트 확인
서버 (Render)AI 추출 요청 처리, HWPX 문서 생성
Claude API연구 정보 추출과 초안 작성
Supabase데이터 저장

선택 이유: 서류마다 AI가 따로 쓰면 다시 어긋날 수 있어 사실 시트를 중심에 두었고, 기관 양식이 한글 파일이라 HWPX로 바로 출력했습니다. AI 호출과 문서 생성은 서버에서 처리해 화면은 입력과 확인에 집중하게 했습니다.

8범위와 현황

구현 · 시험유형 선택 · 질문 입력 · 초안 추출, 사실 시트 · PI 확인 목록, HWPX 생성 · 주소 검색 (자동 테스트 210개)
미완성서류 간 자동 일치 검사, e-IRB 입력 지원, PI 최종 확인, 로그인 설정
도입 전 과제민감정보 처리, 국내 저장 위치, 보안

구현 기록 기준 2026.10.15. 210개 테스트는 실사용 성공률과 별개입니다.

9검증 계획

  • 실제 연구자가 신청 서류 초안을 만드는 데 걸리는 시간이 줄어드는가
  • 서류 간 불일치로 인한 보완 요청이 줄어드는가
  • 연구자가 사실 시트 확인 단계를 부담 없이 마치는가
